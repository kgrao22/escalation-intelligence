02

Who does what

Three outside services. Everything else is arithmetic on JSON files on your own machine.

Slack

The filing cabinet. Where the raw conversations live, and where the finished report goes.

  • Reads threads from the source channel
  • Posts the final review to the destination channel
  • Three separate clients: read, post, delete

Anthropic (Claude)

The reader who understands. Reads English and makes judgements about meaning.

  • Reads a thread → fills in a form
  • Compares two threads → same issue?
  • Suggests what to do about a pattern

Voyage AI

The librarian who sorts by topic. Turns sentences into numbers so we can measure resemblance fast and cheaply.

  • Sentence in → 1,024 numbers out
  • Makes no judgements at all
  • Used only to shortlist what to ask Claude

Why both an AI and an embedding service?

This is the question people ask most, so here it is in the simplest terms.

Imagine 269 complaint letters, and you want to find the ones that describe the same problem. You could hand every possible pair to a careful human reader and ask "are these two the same?" — but with 269 letters there are 36,046 pairs. That reader would take forever and cost a fortune.

So instead you do it in two passes:

  1. Voyage sorts the pile roughly. It reads each letter once and gives it a position — like putting letters about billing near other letters about billing. Now you can measure, instantly and almost for free, which pairs are even plausibly about the same thing. That cuts 36,046 pairs down to 1,527.
  2. Claude reads the shortlist carefully. Only those 1,527 promising pairs get shown to the expensive reader, who actually decides "yes, same problem" or "no, just similar words".
The one-line difference

Voyage measures whether two sentences look alike. Claude decides whether they mean the same thing. Looking alike is cheap and often wrong; meaning the same thing is expensive and correct. The pipeline uses the cheap one to decide what to spend the expensive one on.

This matters because looking alike is genuinely unreliable. Two threads can describe the identical defect in completely different words and score low. Two unrelated threads that both mention Stripe can score high. If the system trusted Voyage's numbers to make the decision, it would group things by vocabulary rather than by meaning — which is exactly the mistake this design avoids.

A common misunderstanding

The similarity number (0.60, 0.80) is not a decision that two things match. It only decides which questions are worth paying to ask. Pairs sitting right at the floor are routinely judged "different" by Claude — and that is the system working correctly, not a threshold that needs tuning.

03

What crosses each boundary

Data leaves the machine at only three points. Here is exactly what, and what never does.

BoundaryWhat is sentWhat is never sent
Slack → local Raw thread text, timestamps, permalinks —
local → Anthropic
extraction		 Cleaned thread text (bot noise stripped) Nothing else; this is the only stage that sends raw conversation
local → Anthropic
adjudication & recommendations		 De-identified statements, classifications, counts, dates Thread IDs, permalinks, vectors, raw text, scores, ranks
local → Voyage Short de-identified statements only Thread IDs, permalinks, emails, customer names, policy or Stripe IDs
local → Slack The five finished review messages Anything not in the reviewed preview file

The privacy gate that enforces the Voyage boundary runs before any network call and inspects the exact strings that will be transmitted — rejecting emails, Slack permalinks, HubSpot URLs, Stripe-style identifiers, UUIDs, user mentions and long numeric IDs. Thread IDs and permalinks stay local and are re-attached after the vectors return.

04

The layered view

The same system organised by responsibility rather than by sequence. Each layer only knows about the one below it.

Why the client layer matters

Every external call is a plain function type — SlackPostFn, VoyageEmbedFn, StructuredParseFn. The real implementation is wired in only at the command entry point. A test passes a fake, so a test cannot reach the network even by accident, and cannot cost money.

05

The artifact chain

Each stage reads one file and writes another. This is what makes the pipeline restartable, auditable, and cheap to re-run.

Filename grammar

Every artifact name encodes what it is, so nothing can be mistaken for anything else:

SegmentMeaningExample
prefixwhich stage made itreport
windowhow far back it looked365d
generationalgorithm revision, optionalv2
datewhen it was generated2026-08-14

The two tracks also use different prefixes — embeddings- versus workflow-embeddings- — and the pattern is anchored, so a technical file can never be read as a workflow file.

06

Safety architecture

This system reads a live company channel and writes to another. Four independent layers make damage structurally difficult rather than merely unlikely.

The clearest example: the module that reads Slack has no posting method at all. Not a disabled one — it does not exist. A bug in analysis code therefore cannot post to the source channel, because the capability is absent rather than guarded.

Total: roughly 2,255 Anthropic calls on claude-haiku-4-5 and 5 Voyage calls. The embedding step is almost free and saves roughly 24× on the adjudication step by narrowing 36,046 pairs to 1,527.

Rate limits to know about

The Voyage account is on the free tier — 3 requests per minute. Running both embed steps back to back triggers an HTTP 429. The client has no automatic backoff yet; wait a minute and re-run, or add a payment method to lift the limit.
